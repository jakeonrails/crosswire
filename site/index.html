Hotwire · Rails 8 · Turbo 8

The primitives Hotwire never shipped.

Small, generic Stimulus controllers paired with ERB helpers — so rich UI stays The Rails Way, and you can stop pricing in a React migration.

Stimulus is the wiring tier, not the component tier.

A controller only stays generic if its classes, URLs, ids and bindings are injected from outside. Doing that by hand in ERB is painful enough that people give up and write one-off controllers instead. The helper layer is what makes generic controllers survive contact with a real app — and six production codebases invented it independently without ever writing it down.

Why this exists

The ecosystem doesn't lack knowledge. It lacks packaging.

37signals copy-paste fourteen primitives between Campfire, Writebook and Fizzy — three of them byte-for-byte identical — because there is no way to ship them. A Turbo maintainer built APG-accessible widgets and never published them. Searching GitHub for a Hotwire library with ARIA support returns nothing at all.

So the claim here isn't novelty. It's that someone ships it, documents it, and keeps it working.

Running the real controllers

Every demo below runs the gem's actual source, inlined at build time. Nothing here is a mock.

values · targets · CSS Classes API
You usually should — that's Rule 0, and every presenter's docstring says so. Reach for this only when you need aria-expanded on a real button, an animation hook, persistence, or an event other controllers can listen to.

The open state is server-rendered, so it is correct before JS loads and survives a Turbo morph.

cw--dismiss

cancelable events · focus guard
Draft saved.
Invitation sent to ana@example.com.

Dispatches a cancelable cw--dismiss:dismissing carrying a complete() callback — that seam is where cw--transition hooks in to animate the exit. Node.remove() is synchronous, so without it there is nothing left to animate.

cw--clipboard

live region · graceful failure
bundle add crosswire

Announces into an aria-live region rather than relying on a purely visual "Copied!" state — and the region must already exist in the DOM, because one inserted alongside its content is never announced.

cw--dialog

native <dialog> · scroll lock · morph guard

showModal() gives you more than you think

Escape, inertness and the top layer are free — so delete your focus trap. Scroll lock and focus restore are not free, and this controller adds them.

Guards turbo:before-morph-element: morphing strips open, and per spec that does not call close() — it leaves the whole document inert with close() a silent no-op. A page-freezing bug on the default happy path.

cw--hotkey

composes by clicking

Not opened yet.

On match it dispatches its event and then a synthetic click() on its own element — so it composes with whatever click action is already there instead of needing to know about it. It parses the key spec itself rather than using Stimulus key filters, which are exact-match on modifiers and would silently drop half the combos.

cw--persist

survives reload · survives morph

Tick it and reload the page — it comes back. It also re-applies on turbo:morph-element, scoped to its own element rather than the page-wide turbo:morph@window that once hung a browser with 188 Trix editors. Storage failures (Safari private mode, quota) degrade to memory instead of breaking the page.

no controller at all

Rule 0

This popover has no Stimulus controller. Light dismiss, Escape and top-layer stacking are native popover behaviour. Ask whether the platform already does it before writing a component — of 119 catalogued patterns, 41 need no JavaScript at all.

Every presenter docstring opens with this question. A component library that never tells you to skip it is selling you something.

Composition

There is no modal controller

A modal is five primitives patched together, each independently useful elsewhere. That is the whole design: build a vocabulary, not a catalogue of features.

Corrections

Advice that is now wrong

Thirty-four entries, each verified against Turbo's own source rather than against other blog posts. A sample:

redirect_to path, turbo_frame: "_top"

Does not exist. turbo-rails#367 has been open since 2022. Multiple posts present it as shipped. A Turbo maintainer solved it properly in 2022 with a ~25-line concern that stashes the frame in the flash — and it has sat unread in a branch ever since.

data-turbo-cache="false"

Removed in Turbo 8.0.21 — not deprecated, gone. Use data-turbo-temporary, or the page-level turbo-cache-control meta. data-turbo-morph="false" never existed at all.

reconnect() { this.disconnect(); this.connect() }

Causes exponential listener growth. And the popular turbo:morph@window listener fires page-wide — 188 Trix editors once hung a browser. Use element-scoped turbo:morph-element.

Hotwire ships less JavaScript than React

At framework level it does not: Turbo + Stimulus is 60,715 bytes gzipped against React + ReactDOM's 45,131. The argument only holds at the application-bundle level. Measured, not assumed.

Honesty

Where Hotwire genuinely loses

A library that only tells you what it's good at is selling you something. These came out of the same research, and each has a named escape hatch.

  • Virtualized long lists — windowing fights Turbo's DOM ownership; content-visibility covers ~5k rows, then fence off a JS grid.
  • Spreadsheet-style grid editing — needs a client model with sub-100ms feedback, the inverse of Turbo's philosophy.
  • Optimistic UI with rollback — Turbo's only reconciliation guarantee is dedupe-by-id on append.
  • Character-level collaboration — CRDTs need a binary transport a <turbo-stream> can't express.
  • Typing indicators — drop below Turbo Streams to raw ActionCable.
  • Infinite-scroll back-button state — the snapshot cache is a 10-entry LRU that any successful non-GET submit clears entirely.

The best one-line heuristic came from a practitioner, not a maintainer: "try building a calculator with only turbo." Turbo suits stateless interactions; stateful ones fight it.
