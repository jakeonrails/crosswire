cw.menu

CSS over the shipped role=menu widget — item hover/focus/checked states, a documented [role=separator] treatment the partial itself never emits, a .cw-menu__item--danger modifier, and disabled styling.

<%# The standard partial's `items:` array already supports role:/checked: per item —
    aria-checked drives menu.css's checkmark, reserved on every checkbox/radio item
    (checked or not) so unchecked siblings never jump when one toggles. %>
<%= cw.menu "View", id: "gallery-menu-checked", items: [
      { label: "Show hidden files", role: "menuitemcheckbox", checked: true, value: "hidden" },
      { label: "Show line numbers", role: "menuitemcheckbox", checked: false, value: "lines" },
      { label: "Compact", role: "menuitemradio", checked: false, value: "compact" },
      { label: "Comfortable", role: "menuitemradio", checked: true, value: "comfortable" }
    ] %>

site/examples/menu/danger-and-separators.html.erb

<%# .cw-menu__item--danger and [role="separator"] are documented classes the
    standard `items:` partial never emits on its own (see menu.css's own header
    comment) — cw.menu_for (compose-yourself) is how a caller reaches for either,
    mirroring exactly what _menu.html.erb itself does per item. %>
<%= cw.menu_for id: "gallery-menu-danger" do |m| %>
  <div <%= cw_attrs(m.root_attrs) %>>
    <button <%= cw_attrs(m.button_attrs, class: "cw-menu__button") %>>Row actions</button>

    <div <%= cw_attrs(m.menu_attrs, class: "cw-menu__list") %>>
      <button type="button" <%= cw_attrs(m.item_attrs(value: "duplicate"), class: "cw-menu__item") %>>Duplicate</button>
      <button type="button" <%= cw_attrs(m.item_attrs(value: "archive"), class: "cw-menu__item") %>>Archive</button>

      <div role="separator" class="cw-menu__separator"></div>

      <button type="button" <%= cw_attrs(m.item_attrs(value: "restore"), class: "cw-menu__item", disabled: true) %>>Restore (unavailable)</button>
      <button type="button" <%= cw_attrs(m.item_attrs(value: "delete"), class: "cw-menu__item cw-menu__item--danger") %>>Delete</button>
    </div>
  </div>
<% end %>

Props

No declared variants — CSS-only styling of the existing primitive; see its own keyword arguments.

Morph contract

Morph: Preserved
  DOM-only state: whether the menu is open, and which item currently holds
    `tabindex="0"` (assigned by the composed `cw--roving-focus`, never by this
    controller — see the class docstring's composition map). Same shape as
    `Crosswire::Presenters::Popover`'s own verdict: `cw--menu` renders NO
    Stimulus values at all (the class docstring: "STATE LIVES IN THE BROWSER,
    NOT A STIMULUS VALUE... nothing here for Turbo 8 morphing to clobber or to
    register with usePreserve"), because open/closed is the same native
    popover top-layer state `cw--popover` already leans on underneath it.
  On morph: with nothing expressed as a DOM attribute, an in-place morph over
    the wrapper has nothing to patch that would change open/closed — proven, not
    merely asserted, against real `@hotwired/turbo` (browser test 18: "an open
    menu survives `Turbo.morphElements()` over its wrapper, still open, with
    focus unmoved"). The one REAL residual hazard is different in kind: a
    background stream replacing `item` elements while the menu is open, which
    `itemTargetDisconnected` (R8) plus `cw--roving-focus`'s own stop-handoff
    cover directly — not a "state was clobbered" bug, but "the items themselves
    changed out from under an open menu," which no preserve mechanism could fix
    either.
  The app must: nothing beyond the ordinary rule for a Stimulus controller with
    no server-rendered state to keep correct — there is no `open:` kwarg here for
    a response to get wrong the way `Crosswire::Presenters::Dialog#open` can.

CSS

/* crosswire/ui/menu.css — CSS over the shipped `_menu.html.erb` widget
   (Crosswire::Presenters::Menu), ui-tier-spec.md §5 item 10. NO markup, NO presenter,
   NO helper change — cw-menu / cw-menu__button / cw-menu__list / cw-menu__item all
   already exist on the shipped partial. Two classes below are NEW and documented,
   not emitted by the partial itself (a caller adds them via `cw.menu_for`/an
   `item_attrs` override — see site/examples/menu/danger-and-separators.html.erb):

     .cw-menu__item--danger   a destructive command (Delete, Remove…)
     .cw-menu__separator      an alias for [role="separator"] — style either one; the
                               partial never emits an element with this role at all
                               (a caller renders one by hand inside `cw.menu_for`), so
                               `[role="separator"]` alone is the real, load-bearing
                               selector and the class is a documented convenience.

   Every color/length below is either a global token or one of THIS component's own
   `--cw-menu-*` knobs, always consumed through `var(...)`. */

@layer crosswire.components {
  .cw-menu {
    display: inline-block;
  }

  .cw-menu__button {
    --cw-menu-button-font: inherit;

    font: var(--cw-menu-button-font);
  }

  .cw-menu__button:focus-visible {
    outline: none;
    box-shadow: var(--cw-shadow-focus);
    border-radius: var(--cw-radius-sm);
  }

  .cw-menu__list {
    --cw-menu-bg: var(--cw-color-surface-raised);
    --cw-menu-fg: var(--cw-color-fg);
    --cw-menu-border: var(--cw-color-border);
    --cw-menu-radius: var(--cw-radius-lg);
    --cw-menu-py: var(--cw-space-2);
    --cw-menu-min-width: 12rem;

    margin: 0;
    min-width: var(--cw-menu-min-width);
    border: var(--cw-border-width) solid var(--cw-menu-border);
    border-radius: var(--cw-menu-radius);
    padding: var(--cw-menu-py) 0;
    background: var(--cw-menu-bg);
    color: var(--cw-menu-fg);
    font-family: var(--cw-font-sans);
    font-size: var(--cw-text-sm);
    line-height: var(--cw-leading-normal);
    box-shadow: var(--cw-shadow-2);
  }

  .cw-menu__item {
    --cw-menu-item-px: var(--cw-space-4);
    --cw-menu-item-py: var(--cw-space-2);
    --cw-menu-item-checked-width: var(--cw-space-5);
    --cw-menu-item-hover-bg: var(--cw-color-surface-sunk);
    --cw-menu-item-danger-fg: var(--cw-color-danger);
    --cw-menu-item-danger-hover-bg: var(--cw-color-danger-subtle);
    --cw-menu-item-check-top: 50%;
    --cw-menu-item-check-transform: translateY(-50%);

    display: block;
    width: 100%;
    box-sizing: border-box;
    border: 0;
    background: transparent;
    color: inherit;
    text-align: left;
    text-decoration: none;
    cursor: pointer;
    appearance: none;
    font: inherit;
    padding: var(--cw-menu-item-py) var(--cw-menu-item-px);
  }

  /* Reserve room for the checkmark that [aria-checked="true"] adds below, on EVERY
     checkbox/radio item — checked or not — so unchecked siblings don't jump when one
     item toggles. Plain "menuitem"s (no role attribute check needed: this selector
     only matches the two roles that ever carry aria-checked) get no reserved gutter. */
  .cw-menu__item[role="menuitemcheckbox"],
  .cw-menu__item[role="menuitemradio"] {
    position: relative;
    padding-left: calc(var(--cw-menu-item-px) + var(--cw-menu-item-checked-width));
  }

  .cw-menu__item[aria-checked="true"]::before {
    content: "✓";
    position: absolute;
    left: var(--cw-menu-item-px);
    top: var(--cw-menu-item-check-top);
    transform: var(--cw-menu-item-check-transform);
    color: var(--cw-color-accent);
  }

  .cw-menu__item:hover,
  .cw-menu__item:focus-visible {
    background: var(--cw-menu-item-hover-bg);
  }

  .cw-menu__item:focus-visible {
    outline: none;
  }

  .cw-menu__item[disabled],
  .cw-menu__item[aria-disabled="true"] {
    color: var(--cw-color-fg-subtle);
    cursor: not-allowed;
  }

  .cw-menu__item[disabled]:hover,
  .cw-menu__item[aria-disabled="true"]:hover {
    background: transparent;
  }

  /* ---- danger modifier — NOT emitted by the partial; see the header comment ----- */
  .cw-menu__item--danger {
    color: var(--cw-menu-item-danger-fg);
  }

  .cw-menu__item--danger:hover,
  .cw-menu__item--danger:focus-visible {
    background: var(--cw-menu-item-danger-hover-bg);
  }

  /* ---- separator — [role="separator"] is the real selector; see header comment -- */
  [role="separator"].cw-menu__separator,
  .cw-menu__list [role="separator"] {
    height: var(--cw-border-width);
    margin: var(--cw-space-2) var(--cw-space-3);
    background: var(--cw-color-border);
    border: 0;
  }
}
