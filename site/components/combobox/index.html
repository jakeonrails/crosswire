cw.combobox

site/examples/combobox/active-option.html.erb

<%# The "active" option class is opt-in (Stimulus Classes API) and applied by the
    controller at RUNTIME during keyboard navigation — active_class:
    "cw-combobox__option--active" wires it up (see combobox.css's own header on why
    there is no default). To show the CSS without JS, this compose-yourself example
    puts the class on one option by hand, exactly where the controller would put it. %>
<%= cw.combobox_for id: "gallery-combobox-active", name: "record[state]",
      label: "State", expanded: true, active_class: "cw-combobox__option--active",
      value: "CA", display: "California" do |c| %>
  <div <%= cw_attrs(c.root_attrs) %>>
    <label <%= cw_attrs(c.label_attrs) %>>State</label>
    <div class="cw-combobox__control">
      <input type="text" <%= cw_attrs(c.input_attrs) %>>
      <input <%= cw_attrs(c.field_attrs) %>>
    </div>
    <ul <%= cw_attrs(c.listbox_attrs) %>>
      <li <%= cw_attrs(c.option_attrs(value: "CA", display: "California", selected: true), class: "cw-combobox__option cw-combobox__option--active") %>>California</li>
      <li <%= cw_attrs(c.option_attrs(value: "NY", display: "New York"), class: "cw-combobox__option") %>>New York</li>
      <li <%= cw_attrs(c.option_attrs(value: "TX", display: "Texas"), class: "cw-combobox__option") %>>Texas</li>
    </ul>
  </div>
<% end %>

Morph contract

Morph: Preserved
  DOM-only state: the selected `value` and whether the listbox is `expanded`.
    Unlike `Crosswire::Presenters::Popover`/`Menu`, this controller DOES declare
    ordinary Stimulus values for both (`value`/`expanded`, per `root_attrs`
    above), so there is a real attribute a morph could patch out from under a
    choice the user already made client-side.
  On morph: `static preservedValues = ["value", "expanded"]`, guarded by
    `usePreserve(this)` (called in `connect()`, AFTER the controller has
    re-rendered from its own values and flipped internal readiness — see the
    controller's own comment on that ordering) — the same `crosswire/morph`
    mechanism `cw--disclosure`/`cw--dialog`'s sibling primitives use. A
    divergence check (B2) means the SERVER still wins whenever this controller
    has not itself written a value since the last sync — the guard only stops a
    background morph from silently reverting a write THIS controller actually
    made. KNOWN RESIDUAL, documented rather than papered over: the characters the
    user has typed live in the visible `input` element's `value` PROPERTY, a
    DESCENDANT of the element `usePreserve` guards — `createMorphGuard`'s B1
    per-element scoping means a guard on the root cannot reach a descendant's
    property, by design, no matter what `preservedValues` lists.
    `aria-activedescendant`/the active option are correctly NOT preserved: they
    are transient client-only navigation state with no server-rendered
    counterpart, and morph legitimately invalidates them. Proven, not merely
    asserted, against real `@hotwired/turbo` in
    `test/js/combobox_controller.browser.test.js` (tests 20/21) — the docstring
    claims exactly what the code is observed to do, no more.
  The app must: narrow the SERVER-SIDE update's scope with
    `turbo_stream.replace(target, method: :morph)` so this combobox's own subtree
    is never the thing being morphed INTO — that is `crosswire/morph`'s own Rule
    0, and it is the only way to close the descendant-`value`-property residual
    above; `usePreserve` alone cannot reach it.

CSS

/* crosswire/ui/combobox.css — CSS over the shipped `_combobox.html.erb` widget
   (Crosswire::Presenters::Combobox), ui-tier-spec.md §5 item 12. NO markup, NO
   presenter, NO helper change — every class below already exists on the shipped
   partial (cw-combobox / __label / __control / __input / __clear / __listbox /
   __option / __empty / __status).

   ACTIVE OPTION — the controller (combobox_controller.js) applies its `activeClass`
   to the currently-active option ONLY when the presenter was given `active_class:`
   (Stimulus's Classes API: `this.hasActiveClass` guards it, per that controller's
   own docstring on why every crosswire controller must guard an optional class this
   way) — there is no default active-option class emitted for free. `.cw-combobox__
   option--active` below is the CONVENTION this file styles; wire it up with
   `active_class: "cw-combobox__option--active"` on `cw.combobox`/`cw.combobox_for`
   (see site/examples/combobox/active-option.html.erb). [aria-selected="true"] is
   separate and always available with zero configuration — it marks the PRESELECTED
   option (R4, from `value:`/`display:`), independent of which option is merely
   "active" during keyboard navigation.

   Every color/length below is either a global token or one of THIS component's own
   `--cw-combobox-*` knobs, always consumed through `var(...)`. */
